01. Data and split¶

Lead: Keshav. Goal: check the data and keep past and future separate.

Class = 0 means legitimate. Class = 1 means fraud. Class is an answer used for filtering and evaluation, never an input feature. Time is elapsed seconds, so it orders the transactions.

Why this notebook comes first: every later result depends on these rows. If a check here fails, or past and future rows mix, the autoencoder, GMM and hybrid comparisons would all be unreliable.

2. Remove exact repeats, then split by time¶

We retain Phase 1's assumption that exact duplicate rows are repeated records. Without transaction IDs, we cannot prove that every duplicate is an accidental copy. Removing them avoids exact repeats across periods. Keep this assumption visible when discussing results.

Training = earliest 60%; validation = next 20%; test = last 20%. Training teaches the model. Validation controls stopping and cutoffs. Test reports the final comparison.

Why time order, not a random split: a deployed model learns from the past and scores the future. A random split would let training rows come from after test rows, which leaks future patterns and makes results look better than they would be in practice.

Order of operations in the code:

  1. sort_values("Time", kind="stable"): put rows in time order; rows with the same second keep their file order.
  2. drop_duplicates(): keep the first copy of each exact repeat.
  3. iloc[:train_end] and so on: cut by row position at 60% and 80%.

Phase 1 cut at a Time value; here we cut at a row position. The assert lines prove both give the same rows: identical counts and fraud counts, and no period overlaps the next.

data = raw.sort_values("Time", kind="stable").drop_duplicates().reset_index(drop=True)
n = len(data)
train_end, validation_end = int(0.6*n), int(0.8*n)
parts = {"train": data.iloc[:train_end],
         "validation": data.iloc[train_end:validation_end],
         "test": data.iloc[validation_end:]}
rows = []
for name, part in parts.items():
    part.to_csv(P2 / "models" / f"{name}.csv", index=False)
    rows.append({"split": name, "rows": len(part), "frauds": int(part.Class.sum()),
                 "legitimate": int((part.Class == 0).sum()),
                 "fraud_rate_pct": 100*part.Class.mean(),
                 "first_second": part.Time.min(), "last_second": part.Time.max()})
splits = pd.DataFrame(rows)
display(splits.round(4))
assert list(splits.rows) == [170235, 56745, 56746]
assert list(splits.frauds) == [342, 57, 74]
assert parts["train"].Time.max() <= parts["validation"].Time.min()
assert parts["validation"].Time.max() <= parts["test"].Time.min()
splits.to_csv(P2 / "results/splits.csv", index=False)
(P2 / "results/data_audit.json").write_text(json.dumps({
    "raw_sha256": sha256, "raw_rows": len(raw), "raw_frauds": int(raw.Class.sum()),
    "duplicates_removed": len(raw)-n, "clean_rows": n,
    "clean_frauds": int(data.Class.sum()), "missing_cells": 0,
    "duplicate_policy": "Remove exact repeats, preserving Phase 1 assumption"}, indent=2))

Cleaning removed 1,081 exact repeats (19 of them labelled fraud), leaving 283,726 rows and 473 frauds.

The time ranges show the periods do not overlap: training ends at second 120,392 and validation starts at 120,393. Training covers about 33 hours, validation about 7 hours and test about 8 hours. They hold 60/20/20% of the rows, not of the hours, because night-time hours contain far fewer transactions.

The base rate differs between periods (0.20%, 0.10%, 0.13%). Fraud does not arrive evenly over time, so precision on the test period depends on its own base rate.

The line Out[3]: 305 is only the number of characters written to data_audit.json; it is not a result.

3. Visual: fraud is rare and its frequency changes¶

The left plot uses counts; the right uses percentages. Neither model is trained to maximize accuracy. At test prevalence, always predicting legitimate would be about 99.87% accurate while catching no fraud.

The left plot uses a log scale: each step up the axis is ten times the previous one. On a normal scale the fraud bar would be almost invisible.
